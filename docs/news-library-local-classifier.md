# Локальний оцінювач: кандидат Laya

Дата перевірки: 2026-10-09. Користувач запитав про можливість використання
моделей з https://www.jevtypesafeai.com/jev/local. Це дослідження кандидата;
модель не встановлена, її якість і швидкість на наших даних не виміряні.
Погоджений основний маршрут Ollama cloud / OpenRouter free не змінено.

## Уточнення: готові API Ollama та OpenRouter

Після додаткового посилання користувача перевірено
[анонс Ollama від 2026-09-29](https://ollama.com/blog/ollama-now-supports-jev-style-decision-models).
Ollama від 0.35 підтримує `/v1/systemone` та типи `choice`, `noul`, `score`.
Моделі анонсу: `nimble` 9B, `tev1` 4B і `tev1:0.8b`. Це локальні
варіанти; хмарні в анонсі описані як майбутнє доповнення. У перевірених
списках тегів nimble/tev1 cloud-варіантів не знайдено. Локальний
`/api/version` повернув `0.35.0`; inference через новий endpoint не перевірено.

OpenRouter має окремі decision-моделі. На сторінці
[`inception/mercury-decide:free`](https://openrouter.ai/inception/mercury-decide:free)
заявлено System One API, типізовані відповіді та нульову ціну входу й виходу.
Це перспективний кандидат для хмарного пілота без локальної моделі.
[`typesafe/jev-1.13`](https://openrouter.ai/typesafe/jev-1.13/)
натомість має платний вхід і не відповідає поточній вимозі free.

Статус перевірки: прочитані публічні сторінки та версія локального сервісу.
Загальний OpenRouter `/api/v1/models` у цій перевірці не показав Mercury
Decide; доступність decision endpoint з обліковим записом ще не перевірена.
Наявність сторінки моделі не прирівнювати до успішного виклику.
Не припускати, що генеративний маршрутизатор `openrouter/free` підтримує
System One: для експерименту потрібен окремий явний ID decision-моделі.

Оновлена пропозиція: спочатку перевірити хмарний decision API, Laya
залишити локальним кандидатом. Це пропозиція до пілота, а не автоматична
зміна погодженої ролі OpenRouter як резерву. Будь-який decision API
викликається після правил без ШІ; дайджест і текстове пояснення
залишаються окремим завданням генеративної моделі.

## Технічна здійсненність

Перевірене обладнання: Linux x86_64, Ryzen 7 7700, 61 GiB RAM.
Для CPU-пілота перспективна Laya, зокрема multilingual для українського
тексту. Це окремий класифікатор, не генератор дайджестів.
[ONNX-обгортка](https://github.com/receptron/laya) підтримує CPU;
для її базової моделі заявлено близько 2 GB RAM плюс пам'ять запитів.
Точні витрати multilingual і затримки тут ще потрібно виміряти.

За [карткою автора](https://huggingface.co/convaiinnovations/laya),
multilingual має 322M параметрів, типовий ліміт 1024 токени й можливість
збільшення до 8192. Частина контексту відводиться запитанню та варіантам.
Довгі статті не можна мовчки обрізати й оцінювати як повністю прочитані.

## Застосування в бібліотеці

Пропонований експериментальний потік:

1. Наявні дешеві правила без ШІ.
2. Laya оцінює тематику, конкретику та ознаки реклами.
3. Хмарна модель формує дайджест і коротке пояснення.

Laya повертає категорії, розподіли й оцінки; текстового Reasoning не пише.
Особисту новизну неможливо визначити лише зі статті без контексту того,
що користувач уже знає. Корисність у майбутньому залишається позитивним
сигналом. Результати моделі не стають автоматично незалежними причинами
для формули відсіву.

## Перевірка перед застосуванням

Автор попереджає про слабкі базові результати на нових задачах,
надмірну впевненість та необхідність калібрування на власних даних.
Тому почати з оцінювання без впливу на видимість матеріалів: Clippings
`0/1/2`, поділ за джерелами з усуненням витоку дублів, окрема перевірка
українських текстів. Порівняти помилковий відсів цікавого, ранжування,
затримки й виграш у хмарних викликах. Навчання та перевірка — різні дані.

Не ототожнювати ймовірність «цікаво» з упевненістю моделі у вибраній
відповіді: вона може впевнено вибрати «нецікаво».
[OpenJev](https://github.com/razorback16/openjev), наприклад, визначає
confidence через ентропію розподілу; це не готовий рейтинг інтересу.
Рішення про включення локального оцінювача приймати за результатами пілота.
