## Сила відсіву

Контракт: `R = 1 - product(1 - p_i)`, відсів при `R > T` (див. REQUIREMENTS,
«Правила раннього відсіву»). Обґрунтування й застереження:

- Приклад: внески 60% і 50% дають 80%. Немає спрацювань → R=0; внесок 0 нічого
  не змінює; внесок 1 дає R=1. Еквівалентно: залишок `S = product(1 - p_i)`,
  відсів при `S < 1 - T`; S — «немає достатніх підстав для відсіву», а не
  Confidence оцінювача.
- Незалежність причин — припущення користувача, на даних не встановлена.
  Тому R — сила відсіву, а не відкалібрована ймовірність нецікавості.
  Це не формула об'єднання кількох оцінок ймовірності тієї самої події.
- Невизначеність через брак тексту чи даних — не негативний сигнал і R не
  збільшує. Відсутній прогноз моделі = «не виконувався через фільтр», а не
  Confidence=0.
- Ідея, не реалізація: для семантичних правил зберігати силу правила `w` і
  впевненість відповідності `c`, внесок `p = w*c` (точний збіг тега дає c=1, але
  не обов'язково w=1).
- Повторний підрахунок: синоніми та правила однієї причини об'єднувати в групу,
  брати максимальний внесок у групі й поєднувати групи за формулою. Це лише
  обмежує подвійний підрахунок, незалежності груп не доводить. Багато слабких
  спрацювань також можуть перевищити поріг, тож кожне правило має мати
  конкретну причину й не дублювати наявні.
- Правила раннього етапу використовують лише безкоштовне: URL, джерело,
  наявні теги/категорії, текст, явні зіставлення. Семантична відповідність
  новою ШІ-оцінкою до раннього етапу не належить.

## Словник і шкала lance-agent

Довідка для ідей, не залежність. У `lance-agent/.data/skills.csv` було 120
рядків, у `tags.csv` — 39 (колонки name, confidence, skip; усюди confidence=50).
Код фільтрує за `skip` і канонічними ID категорій/тегів, суму ймовірностей не
обчислює; CSV — початкові дані, не перевірений поточний стан бази. Частина
seed-виключень стосується вибору freelance-замовлень (Python, Rust, дизайн) і
не означає нецікавості інформації про ці теми. Для новин правила добирають
окремо, не копіюючи skip-позначки чи значення 50.

Рівні Confidence у lance-agent (межі реалізації, не дослівна шкала WEP з wiki):
Remote 0–14, Unlikely 15–39, Possible 40–69, Probable 70–89, Almost Certain
90–100. Для бібліотеки Confidence — прогноз оцінювача, що користувач визнає
матеріал цікавим і змістовним (зокрема на перспективу), а не виміряна
ймовірність і не істинність тверджень статті. Власна шкала користувача —
estimative usefulness (REQUIREMENTS).

## Кандидати для оцінювання без генерації (не перевірені)

Окреме дослідження 2026-10-09; модель не встановлено, якість і швидкість на
наших даних не виміряно. Основний маршрут (Ollama cloud, OpenRouter free) не
змінюється. Будь-який такий оцінювач працював би після правил без ШІ, а дайджест
і пояснення лишилися б завданням генеративної моделі.

- **Laya** (локальний класифікатор, ONNX на CPU; multilingual 322M параметрів,
  типовий ліміт 1024 токени, до 8192): оцінює тематику, конкретику, ознаки
  реклами; тексту не пише. Довгі статті не можна мовчки обрізати й вважати
  прочитаними. Автор попереджає про слабкі базові результати на нових задачах і
  потребу калібрування. Перевірка — без впливу на видимість: Clippings `0/1/2`,
  поділ за джерелами без витоку дублів, окремо українські тексти.
- **Ollama System One** (від версії 0.35): endpoint `/v1/systemone`, типи
  `choice`, `noul`, `score`; локальні `nimble` 9B, `tev1`. Хмарних варіантів
  не знайдено, inference не перевірено.
- **OpenRouter decision-моделі**: `inception/mercury-decide:free` заявлено з
  нульовою ціною, доступність з обліковим записом не перевірена;
  `typesafe/jev-1.13` платна, умові free не відповідає. Маршрутизатор
  `openrouter/free` не обов'язково підтримує System One: потрібен явний ID.
- Не ототожнювати ймовірність «цікаво» з упевненістю у вибраній відповіді:
  модель може впевнено вибрати «нецікаво». Вимірювати помилковий відсів, ранжування,
  затримки й виграш у хмарних викликах на окремих даних.

## Подальші можливості (черговість не погоджена)

Автоматичний збір новин, адаптація пошукових запитів, рейтинг джерел за
результативністю добірок і підтвердженими помилками, масове опрацювання
архівів, перенесення на VPS (дані й чергу переносити без нового імпорту;
ресурси для локальної `bge-m3` на сервері перевірити окремо), вхідні команди
Telegram-бота через long polling. Пошук: підбір під опис задачі з поясненням,
чому матеріал допоможе, та пошук подібного від знайденої статті.
Зверніть увагу: Telegram-повідомлення має бути корисним самостійно, бо
локальні посилання на сайт не відкриються з іншого пристрою.
