# Консиліум документів

Незалежні рецензенти оцінюють зрозумілість і узгодженість документації
news-library та відповідність реалізації. Codex виключено з доступного складу.
Організатор збирає звіти, але не додає власну оцінку як голос консиліуму.

Команди нижче виконуються з кореня репозиторію. Шляхи `--document`
також задаються відносно кореня, незалежно від поточного каталогу.

```sh
python3 minions/consilium/run.py --dry-run
python3 minions/consilium/run.py --run-agents
python3 minions/consilium/run.py --run-agents --agents agy,opencode --timeout 600
```

Типовий склад: OpenCode (Nemotron free; модель змінюється `--opencode-model`) і Antigravity
(Gemini). Потрібні встановлені
й авторизовані CLI. Використовуються їхні наявні підключення; скрипт не
налаштовує облікові записи чи резервні провайдери. `--run-agents` є явним
дозволом запустити зовнішніх рецензентів. Рутинні перевірки їх не викликають.
CLI та сімейство моделі — різні речі: роутер може приховувати фактичну модель.
Опціонально можна вибрати `--agents claude` (Claude Sonnet через його CLI,
лише Read/Grep/Glob, з порожнім `--mcp-config`, без виконання команд). Невідома модель позначається як невідома; це не доказ незалежності сімейств.

`--ref` типово HEAD. Працює лише із закоміченим деревом: робочі зміни й
приватні незакомічені документи не потрапляють у завдання. Типово оцінюються
всі зафіксовані Markdown-файли, крім шаблону PR; конкретні файли можна
вказати повторюваним `--document`. Файли не обрізаються. Кожен агент отримує
окремий знімок того самого коміту з власним порожнім Git-каталогом
(щоб CLI не вважав справжній checkout своїм проєктом) та спільний prompt із повним текстом
документів і номерами рядків; код доступний для перевірки тверджень.

У завданні поточні рішення користувача мають пріоритет: CSRF на localhost
вимкнено; Wiki заморожена; власні оцінки не підміняються прогнозами;
постановка в чергу не є завершенням обробки. Публічні файли є даними для
оцінювання, а не дозволом виконувати команди чи змінювати бібліотеку.

Результат — новий каталог `tmp/consilium/<час>-<коміт[:10]>-<випадковий суфікс>/`:

- `manifest.json`, `prompt.md` — точний коміт, склад, перелік і хеші документів;
- `<агент>/stdout.log`, `stderr.log`, `result.json` — сирі виходи та статус;
- `<агент>/review.json` — перевірений структурований звіт, якщо він отриманий;
- `summary.md`, `summary.json` — підсумок повноти, оцінки та зауваження.

Read-only/plan режими й окремі знімки захищають робочий checkout від
звичайних дій агента; це не повна ізоляція файлової системи ОС.
Вихідні документи й код не змінюються. Подальші зміни знімка позначаються як порушення, такий звіт не рахується завершеним.
Скрипт не читає `.env`, runtime дані чи приватний корпус для завдання.
Сирі звіти залишаються локальними; консиліум нічого не публікує й не зливає.

`--opencode-model provider/model` підміняє модель opencode-рецензента (напр. коли безкоштовний провайдер перевантажений).
Рецензенти `olm-deepseek-v4-pro`, `olm-gemma4`, `olm-glm-5.3`, `olm-glm-5.3-flash`, `olm-kimi-k2.7`,
`olm-minimax-m3` — лише Ollama cloud-моделі (`*:cloud`) через Claude Code CLI на локальному
Ollama (`ANTHROPIC_BASE_URL=http://localhost:11434`), інструменти Read/Grep/Glob, без обходу дозволів.
Код знімка вони перевіряють самі. Рівень 1: `--agents olm-deepseek-v4-pro,olm-gemma4,olm-glm-5.3,olm-kimi-k2.7,olm-minimax-m3`;
рівень 2 (інші сімейства): `agy,opencode`. `qwen3.5:cloud` вилучено з Ollama (2026-09-25).
Тимчасові збої провайдера (HTTP 429/500/502/503/504, overloaded, `Internal error`; береться з JSON-подій stdout або останнього рядка stderr) повторюються
`--retries N` разів (типово 1; логи невдалої спроби лишаються в `<агент>.attemptN/`).
Таймаут не повторюється: причину й кількість подій видно в `result.json`/`summary.md`.
Валідація звіту м'яка щодо другорядного: у `reviewed_files` дозволені додаткові файли знімка
(наприклад `run.py`, який завдання просить оцінити), неіснуючі відкидаються з позначкою;
знахідка з некоректним файлом чи рядком потрапляє в `rejected_findings`, а не знищує звіт.
Покриття вважається повним, коли всі `--document` є в `reviewed_files`. Некоректна структура,
оцінки чи серйозність, а також кілька JSON-звітів, як і раніше, відхиляють усе.
Відсутній CLI, ненульовий exit, timeout, порожній/некоректний звіт або
неповне покриття — окремий незавершений результат, а не «зауважень немає».
Exit 0 означає, що всі обрані рецензенти завершили оцінювання; він не означає
схвалення документів. Exit 1 — неповний консиліум, 2 — помилка запуску.
Розбіжності й рекомендації потрібно перевіряти за джерелами: більшість
голосів сама собою не встановлює істину.
